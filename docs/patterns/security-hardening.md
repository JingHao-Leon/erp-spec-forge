# 安全加固清单：来自真实系统反模式的教训

> 来源：对两套真实生产系统的**授权**安全评估（已匿名化，不含可定位信息）。每条都是实际观察到的问题，不是理论风险。用途：在你用 erp-spec-forge（或任何工具）设计 ERP 时逐条对照。

## 反模式速查

| # | 反模式（真实观察到） | 风险 | 加固建议 |
|---|---|---|---|
| 1 | 系统参数表里**明文存储**第三方凭据（短信/实名认证/邮箱/支付密钥），后台可读可改 | 任何能进后台的账号可拖走全部对外凭据 | 凭据进密钥服务或加密存储；配置页只显示掩码；轮换有审计 |
| 2 | **EOL 运行时**长期服役（如停更十年的 Web 容器） | 已知漏洞面巨大且无补丁 | 升级计划进排期；至少置于 WAF/网关之后 |
| 3 | 验证码策略为"**失败 N 次后才启用**"，且口令明文 POST | 在线爆破窗口期完全裸奔 | 登录全程验证码/限速；口令走 TLS + 前端不回显 |
| 4 | **默认弱口令**超管账号长期不改 | 一条口令拿下全局 | 交付时强制改密；口令策略 + 定期轮换 |
| 5 | 权限码**全量下发前端**，服务端仅部分校验（UI 过滤当权限） | 改前端即可调用未授权接口 | 服务端逐端点校验功能码；前端权限码仅做展示过滤 |
| 6 | API 鉴权**仅靠会话 Cookie**，无过期策略提示、无操作级二次校验 | 会话固定/CSRF/凭据泄露即全功能暴露 | 会话超时 + CSRF 防护；敏感操作二次确认或 step-up 认证 |
| 7 | **遗留子系统残留**：配置指向已下线的内部网关/测试环境 | 攻击面暴露 + 维护混乱（新人误判架构） | 定期清理死配置；架构图与实际部署对账 |
| 8 | **PII 明文集中**（身份证号、手机号、车牌、住址）且列表页全量展示 | 一处注入即批量泄露 | 敏感字段加密存储 + 展示脱敏；导出权限单列 |
| 9 | 客户级 **API 凭证后台明文可查** | 冒用客户身份调 API | 凭证仅创建时可见（哈希存储）；支持客户自助轮换 |
| 10 | 双系统并行时**同步键无一致性校验** | 同步错位 → 发错货/错账 | 同步键唯一约束 + 定期对账任务（示例规格的 `external_code` 即为此设计） |

## 在 spec 层能做什么

规格驱动的价值之一是把安全约定**前置到设计**：

- `lockable` 三件套让禁用动作带操作人与时间——审计有据
- `auditable` 让单据天然携带 created_by / updated_at——追责链完整
- 功能码矩阵（`rbac/matrix.csv`）可直接作为**服务端鉴权中间件的路由表**，避免"前端过滤当权限"
- 示例规格中的 `operation_log`、`admin_user.password_hash`（注释 bcrypt/argon2）、`sys_config`（注释敏感值须加密）都是把教训写进模型的占位

## 一句话

上面 10 条没有一条是新技术问题——全是"设计时没人写下来，运行时没人回头看"。规格驱动 + 本清单做 PR 门禁，就是解法。
